# Archived Arcade Experiments

These exploratory games are not part of the main demo lineup. See
[Doom, Tetris, and Pong](../demos/README.md) for the maintained demo index.
The original runners and shared helpers remain available for reproducibility.

Six small, reproducible game demos, with the frozen Jiffy model selecting every
player action through `JevProtocol`. No scripted policy fallback, auto-aim,
policy training, or action replacement is used in model mode.

| Demo | Environment | Objective |
| --- | --- | --- |
| Wilds | Original miniature survival/crafting game | Gather food/wood and build a shelter |
| Apex | Gymnasium CarRacing-v3, Box2D | Follow the track |
| Hold | Original miniature tower defense | Defeat 18 attackers and protect the base |
| Duel | Original miniature turn-based robot battle | Defeat the opposing robot |
| Service | Original miniature kitchen game | Prepare and serve three soups |
| Descent | Gymnasium LunarLander-v3, Box2D | Land safely on the pad |

The original games are deliberately small demonstration environments, not
Minecraft, Pokemon, or Overcooked, and do not use commercial game assets.
Their art is generated by the renderer. The engine owns normal game rules
(for example, tower targeting and enemy attacks), not the player's choices.

```bash
pip install -e '.[games]'
python -m examples.arcade --output artifacts/arcade-jiffy
```

Select games with `--games racing lander`, change the limit with
`--max-decisions 180`, and change video playback using `--speed 2` (default).
Output directories must be new. `--smoke --max-decisions 4` checks all engines
and encoders without a GPU/model, with a visibly labeled scripted policy.

Each directory contains `gameplay.mp4`, `preview.png`, `final.png`,
`decisions.jsonl`, `config.json` and `report.json`. `summary.json` records
every completed game and any errors. Videos show the chosen actions,
probabilities and measured inference latency. Top six candidates are shown
when a question has more options; complete probabilities are in the log.

These are **structured-state**, not pixel-control, demos. Racing includes
privileged track geometry; the lander uses the simulator's state vector;
the miniature games expose their current game state. Questions contain the
rules and general task instructions. The simulators pause for inference.
Playback is 2x simulation time, not real-time inference performance; each
video ends with a two-second result frame. No audio is recorded.

These runs are development demonstrations, not held-out evaluations or
comparisons with other models. A failed run is still exported and explicitly
marked as not completing its objective. Latency excludes model loading but
the report's wall time includes a warmup call, rendering and encoding work.

## Compare With Jev

```bash
python -m examples.compare_arcade --reference artifacts/arcade-showcase \
  --output artifacts/arcade-jev --prompt-key
```

Requires `httpx` (included in the dev extra) and a TypeSafe API key, supplied
through a non-echoing prompt or `TYPESAFE_API_KEY`. The adapter uses the direct
TypeSafe endpoint, resolves `jev-latest`, and pins the returned identity for
the rest of the run. It allows at most 1,200 API attempts, retries only 429/529
up to twice, and has no fallback model. No credentials enter output artifacts.

The reference directory must have all six episode subdirectories with their
configurations, reports and complete decision logs. The runner checks initial
state equality, uses the saved questions and decision budgets unchanged, and
records fresh Jev gameplay. It then evaluates Jev on every recorded Jiffy state.
`comparison.json` summarizes outcomes; `paired.jsonl` contains exact-state
answers. Action agreement is not accuracy. Raw rounded API probabilities are
retained; only TVD calculations normalize their sums. Latencies include API
network time for Jev and exclude network for local Jiffy, so they are not a
kernel-speed comparison. One seed is a smoke comparison, not a reliable ranking.
